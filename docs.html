Ajax Modifier 使用说明

一款 Chrome 浏览器扩展，可在任意网页中拦截并修改 XMLHttpRequest 与 fetch 请求/响应， 用于前端调试、问题排查与 Mock 数据开发。

当前版本 v1.5.7 · Manifest V3

1项目简介

Ajax Modifier（原名 Ajax Interceptor）是一个 Chrome 扩展程序。 它通过在页面中注入脚本，劫持全局的 XMLHttpRequest 和 fetch 方法， 在 JavaScript 层面修改网络请求的请求头、请求体以及响应内容，从而影响页面的数据展示与业务逻辑。

与 Charles、Fiddler 等抓包工具不同，本扩展无需配置系统代理， 操作直接在浏览器内完成，只影响当前 Chrome 浏览器中的页面，不会对系统其他应用产生干扰，使用更加轻便。

扩展仅在 JS 运行时修改返回值，DevTools「Network」面板中看到的原始响应不会改变。 页面实际拿到的数据才是被修改后的结果。

2核心功能

🔀

拦截 XHR 与 fetch

同时支持 XMLHttpRequest 和 fetch 两种主流请求方式，覆盖绝大多数前端项目。

📝

修改响应内容

将接口返回替换为自定义 JSON、Mock 随机数据，或通过函数动态处理响应。

⚙️

修改请求（Advanced 模式）

支持修改请求 Headers、GET 查询参数、POST 请求体，实现更精细的调试。

🎯

灵活的 URL 匹配

支持普通字符串匹配和正则表达式匹配，可按 HTTP Method 过滤，支持域名分组。

📦

规则分组管理

按项目/域名分组管理规则，支持组级开关、拖拽排序、单条规则开关与复制。

🎲

Mock.js 随机数据

内置 Mock.js，支持模板语法生成随机 Mock 数据，每次请求可产生不同结果。

📐

ts-mock（TypeScript 接口转 Mock）

粘贴 TypeScript interface 定义，自动转换为 Mock.js 模板，并支持预览生成结果。

💾

配置导入/导出

一键导出所有规则为 JSON 备份文件，可在其他设备或团队中导入复用。

🖥️

双面板位置

支持页面右侧悬浮面板和 DevTools 独立面板两种展示方式，按需切换。

3使用场景

  • 前端开发 Mock 数据 后端接口尚未就绪时，用固定 JSON 或 Mock.js 模板模拟接口返回，前端可独立推进开发，无需等待联调。
  • 联调与 Bug 排查 复现特定数据场景（如空列表、异常状态码、边界值），快速验证页面在各种数据下的展示与逻辑是否正确。
  • 演示与产品验收 在演示环境中将真实接口数据替换为理想数据，避免因测试数据不完整影响演示效果。
  • 权限与状态模拟 通过 Advanced 模式修改请求头（如 Token）或响应体（如用户角色），测试不同权限下的页面行为。
  • 多环境接口切换 按域名分组管理不同项目的拦截规则，在同一浏览器中快速切换不同业务的 Mock 配置。
  • TypeScript 项目快速 Mock 已有 TS 类型定义时，使用 ts-mock 模式直接从 interface 生成 Mock 数据，减少手写模板的工作量。

4安装方式

方式一：Chrome 网上应用店（推荐）

访问 Chrome 应用商店安装，可自动更新： Ajax Modifier - Chrome Web Store

方式二：本地加载（开发者模式）

  1. 构建面板 UI
    进入 iframe 目录，安装依赖并打包： 
    cd iframe
npm install
npm run build
  2. 加载扩展
    打开 Chrome，访问 chrome://extensions/，开启右上角「开发者模式」， 点击「加载已解压的扩展程序」，选择项目根目录 ajax-interceptor。
  3. 验证安装
    浏览器工具栏出现扩展图标，点击可打开配置面板即表示安装成功。

5快速上手

  1. 打开目标网页
    访问你需要调试的网站（如本地开发环境或测试环境页面）。
  2. 打开配置面板
    点击浏览器工具栏中的扩展图标。默认使用「悬浮面板」模式时，面板从页面右侧滑出； 也可在设置中切换为 DevTools 面板模式。
  3. 开启总开关
    面板左上角有一个主开关，打开后扩展开始生效。关闭时图标变灰，不影响页面正常浏览。
  4. 新建规则组
    点击右上角 + 按钮新建一个规则组。可为组设置名称和域名（可选）， 填写域名后匹配将限定在该域名下，只匹配路径部分。
  5. 添加拦截规则
    在组内点击 + 添加规则，填写 URL 匹配关键字（如 api/user/info）， 选择 HTTP 方法和匹配方式，然后在下方编辑器中填写替换内容。
  6. 刷新页面验证
    保存规则后刷新页面，触发对应接口请求，观察页面数据是否按预期被替换。
建议同时打开 DevTools → Network → 勾选「Disable cache（禁用缓存）」， 可提高页面刚加载时 Ajax 请求的拦截成功率。

6规则配置详解

6.1 规则组

规则按「组」组织，每个组可独立开关。组支持以下配置：

配置项说明
组名称备注用途，如「用户中心」「订单模块」
域名可选。填写后（如 api.example.com），组内规则只匹配该域名的请求，匹配关键字只需写路径部分
组开关关闭后组内所有规则暂停拦截，不影响其他组
拖拽排序长按组标题左侧箭头可拖拽调整组的顺序

6.2 单条规则

配置项说明
备注名可选，方便识别规则用途
HTTP MethodALL / GET / POST / PUT / DELETE / HEAD / OPTIONS，限定匹配的请求方法
匹配方式normal：URL 包含关键字即匹配；regex：正则表达式匹配（忽略大小写）
匹配关键字如 abc/getList 或正则 abc.*。填写组域名时只需写路径
规则开关单独控制某条规则是否生效，无需删除规则
复制规则快速复制当前规则到同组，便于创建相似配置

6.3 匹配优先级

当多个规则同时匹配同一请求时，使用规则数组中第一个匹配成功的规则。 可通过调整组的顺序和规则的添加顺序来控制优先级。

6.4 匹配 URL 预览

每条规则下方会显示「匹配范围示意」，展示该规则实际会拦截的 URL 范围， 帮助确认配置是否正确。

7替换模式

每条规则支持四种替换模式，在规则展开区域的「替换模式」下拉框中选择：

7.1 普通 JSON

最简单的方式。在 Monaco 编辑器中直接填写 JSON 字符串，请求匹配成功后， 响应体会被完整替换为你填写的内容。非 200 状态码的响应默认也会被改为 200。 

{
  "code": 0,
  "data": {
    "name": "测试用户",
    "role": "admin"
  },
  "message": "success"
}

7.2 Advanced Mode（高级模式）

通过编写 JavaScript 函数，灵活修改请求和响应。支持三个编辑区域：

编辑区作用适用请求
Headers修改或新增请求头所有方法
Payload修改 GET 的 URL 参数，或 POST/PUT 等的请求体GET 修改 URL；其他方法修改 body
Response根据原始响应动态生成新响应，可修改 status 和 statusText所有方法

Response 函数需返回对象，例如：

// arguments[0] 包含 method、payload、orgResponse、orgStatus 等
const { orgResponse, orgStatus } = arguments[0]
const data = JSON.parse(orgResponse)
data.extra = 'injected by Ajax Modifier'
return {
  response: JSON.stringify(data),
  status: 200,
  statusText: 'OK'
}

7.3 Mock.js

使用 Mock.js 模板语法， 每次请求根据模板随机生成数据。适合需要随机性、列表数据、分页等场景。 

{
  "code": 0,
  "data": {
    "list|5-10": [{
      "id": "@guid",
      "name": "@cname",
      "age": "@integer(18, 60)",
      "email": "@email"
    }],
    "total": "@integer(50, 200)"
  }
}

支持从 TypeScript interface 一键生成 Mock.js 模板（点击「从 TS 生成」按钮）。

7.4 ts-mock

直接粘贴 TypeScript 的 interface 定义，扩展会自动解析类型并生成 Mock.js 模板。 支持常见类型（string、number、boolean、数组、嵌套对象等）， 并根据字段名智能推断（如 billCode 生成 13 位数字）。 可点击「预览」在页面环境中执行 Mock 并查看一次随机结果。 

interface UserInfo {
  id: number
  name: string
  billCode: string
  items: Item[]
}

interface Item {
  title: string
  count: number
}

点击面板右上角「设置」图标，可选择两种面板展示方式：

模式说明适用情况
Suspend（悬浮，默认） 面板嵌入页面右侧，点击扩展图标滑出/收起 日常开发调试，操作最便捷

9工作原理

扩展由多个模块协作完成拦截，数据流向如下：

用户操作面板
iframe UI
→
Service Worker
消息中转
→
Content Script
content.js
→
Page Script
main.js
→
页面 XHR / fetch

各模块职责

模块文件职责
Service Worker service_worker.js 注册 Content Script、转发面板与页面间的消息、管理扩展图标状态
Content Script content.js 在 document_start 时注入页面脚本；悬浮模式下嵌入 iframe 面板
Page Script pageScripts/main.js 在页面上下文中劫持 XHR/fetch，执行规则匹配与数据替换（可访问页面变量）
Mock.js pageScripts/mockjs.js 提供 Mock 随机数据生成能力
配置面板 iframe/ React + Ant Design 构建的 UI，管理规则、设置，数据持久化到 chrome.storage.local
DevTools 面板 devtools.js 在 DevTools 中注册「Ajax Modifier」标签页（仅 DevTools 模式）

拦截流程（简化）

  1. 页面发起 XHR 或 fetch 请求
  2. Page Script 在 open() 阶段根据 URL 和方法匹配规则
  3. Advanced 模式下，在发送前修改 Headers 和 Payload
  4. 请求正常发送到服务器，获取真实响应
  5. 在 onreadystatechange / onload（XHR）或响应读取阶段（fetch）替换响应内容
  6. 页面 JavaScript 拿到的是修改后的数据

11注意事项

关闭缓存：使用扩展时，建议在 DevTools → Network 中勾选「Disable cache」， 避免浏览器缓存导致部分请求未被拦截。
不用时关闭总开关：调试完成后关闭面板左上角的主开关， 扩展图标变灰，页面恢复正常网络请求，避免对日常浏览产生影响。
Network 面板不变：扩展只修改 JS 层面的 response / responseText， DevTools Network 中显示的仍是服务器原始响应。以页面实际渲染结果为准。
刷新同步：修改规则后通常即时生效；切换面板位置、首次安装、 或 DevTools 分离窗口模式下，可能需要刷新页面才能同步配置到 Page Script。
配置备份：点击面板右上角「导出」图标可将所有规则导出为 JSON 文件； 「导入」图标可恢复备份。适合团队共享 Mock 配置或在多台设备间迁移。

常见问题

问题可能原因与解决办法
规则配置了但不生效 检查总开关和组/规则开关是否打开；确认 URL 匹配关键字正确；刷新页面；关闭浏览器缓存
页面加载早期的请求未拦截 在 DevTools 中禁用缓存；确保扩展已启用且页面已刷新
DevTools 模式修改不生效 不要在 DevTools 分离窗口中刷新页面；修改后刷新主页面并重新打开 DevTools
Mock 预览报错 Mock 预览需在 Chrome 扩展环境中运行（非本地 webpack dev server）；检查 JSON 模板格式是否正确
相对路径 URL 匹配失败 v1.5.3+ 已支持相对 URL 自动补全；也可在组域名中指定完整域名后只匹配路径
